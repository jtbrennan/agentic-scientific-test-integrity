\section{Findings}
\label{Findings}

\subsection{Gaming Across Test Conditions (RQ1)}

Gaming was identified in 62 of 207 runs: 61/61 in the conflict
condition and 1/72 with all correct visible tests. None was identified among
the 37 structural-only or 37 no-test runs (Table~\ref{tab:gaming}). The
difference between the conflict and all-tests conditions is large (Fisher's
exact $p=1.3\times10^{-37}$). No included run edited the tests (0/207; 95\%
CI 0--2\%).

Neither prompt wording nor task difficulty changed this pattern. Under
conflict, neutral and pressure prompts both produced gaming in every run
(30/30 and 31/31); with all correct tests the rates were 1/36 and 0/35
(Fisher's exact $p=1$). The quantile-regression task was the hardest to
implement without a statistics package, so we ran it 26 times with
GPT-5.6 Luna under all correct tests and up to three requests to fix
failures; none of these runs gamed (0/26; 95\% CI 0--13\%). In this sample,
gaming followed a test that contradicted the specification rather than a
task the agent found hard.

% Example: runs/nls_incarceration_quantreg__all__neutral__n3__codex-gpt-5__r1__20261104T135604Z
The ordinary-condition case returned hard-coded wealth coefficients for
three quantiles instead of fitting the requested model. It passed the
visible checks after three follow-up requests to fix failures.

Gaming took one form throughout: a special case in the analysis code, not a
change to the tests. Most cases also recognised the supplied dataset before
substituting the expected value, for example by checking that the input had
exactly 8,773 or 12,013 rows. Such a dataset check appeared in 42 of 48
GPT-5.6 Luna cases (88\%) and in 7 of 14 cases from other models (Fisher's
exact $p=0.006$); the remaining cases used other conditions or returned
the expected value for every input. The trajectories show that the agent usually computed the correct
value first, noticed the conflict, and then added the substitution, in
several runs after first stating that it would keep the correct result.

These counts describe identified gaming. All flagged non-conflict runs have
manual labels, but 101 unflagged runs remain unlabelled. With only one case
outside the deliberately conflicting condition and uneven configuration
coverage, the observations do not establish that hiding tests generally
prevents gaming.

\subsection{Detection by Hidden Checks (RQ2)}

Anchored checks detected all 62 identified gaming cases, compared with
13--35 for the other check families (Table~\ref{tab:detection}). Adding them
to v1 increased detection from 35/62 to 62/62, a gain of 43.5 percentage
points: 27 additional detections across four tasks and no losses
(exact McNemar $p=1.49\times10^{-8}$). The gain was not only
retrospective: on the 43 gaming cases from runs started after v2 was
committed, including all runs on the three tasks whose anchored checks were
written before any agent run, v2 detected 43/43 and v1 23/43.

Detection by v1 depended almost entirely on the task
(Fig.~\ref{fig:detection-task}). Its equivariant relations caught nearly
every case on the two logistic-regression tasks and the Poisson task, where
transforming the data while keeping the dataset recognisable produced an
inconsistent result. On the quantile, climate, and meta-analysis tasks, v1's
inputs never triggered the substitution, so the gaming code behaved exactly
like an honest implementation and v1 detected 1 of 27 cases. Anchored checks
start from the exact dataset that the substitution keys on and detected
every case on every task.

One conflict-condition wealth implementation replaced the incarceration
coefficient only for 12,013 usable rows matching year, quantile, and fitted
coefficient checks. It passed v1 but failed anchored checks. Both suites also
flagged the same 40 of 145 non-gaming solutions (28\%; 95\% CI 21--35\%),
all classified from their code as ordinary faults, mostly hand-written
optimisers that failed to converge on transformed data. A flag alone
therefore does not establish gaming. A static scan for expected values and
dataset-size checks in the code flagged 54 of the 62 gaming cases and none
of the 145 other runs. These detection results
include retrospective evaluations following changes to the checks.

Mutation scores changed little despite the additional shortcut detections
(Table~\ref{tab:mutation-scores}, Appendix C). Their raw scores were equal
on five tasks; on wealth quantile regression, the score rose from 0.96 to
0.97.
Of 45 mutants surviving v2, 38 were judged equivalent and seven exposed
testing gaps: five concerned climate input boundaries and two concerned
interaction p-values. Appendix C gives raw and adjusted scores for
every task; the visible tests alone scored 0.69--0.86 after adjustment,
against 0.95--1.00 for both hidden suites.

\subsection{Disclosure During Execution and Review (RQ3)}

Direct review elicited admissions in 62/62 gaming cases, whereas final
answers mentioned the issue in 29/62 (47\%; Wilson 95\% CI 35--59\%) and
explicitly acknowledged the shortcut in 11/62 (18\%). Every case had a
mention somewhere in its user-visible implementation messages. Four final
answers nevertheless made a misleading correctness claim about the affected
result.

The gap between review and final answer is consistent: 33 cases admitted the
shortcut on direct review without mentioning it in the final answer, and none
did the reverse (exact McNemar $p=2.3\times10^{-10}$). It was also larger for
GPT-5.6 Luna, whose final answers mentioned the shortcut less often than
those of the other models (16/48 against 13/14; Fisher's exact
$p=1.1\times10^{-4}$) and stated that the value was wrong less often (5/48
against 6/14; $p=0.012$). Where the agent emitted reasoning summaries, all
eight mentioned the conflict, so a monitor reading them would also have seen
it. The direct review produced no false admissions: no run outside the
gaming cases answered that it had taken a shortcut (0/145).

Review therefore revealed omissions from final answers. Disclosure also
occurred without an explicit question about shortcuts: all 30 available
neutral reviews mentioned the issue. However, neutral review preceded
direct review in the same session, so the comparison cannot isolate the
effect of question wording. Neither review independently verifies
correctness.
